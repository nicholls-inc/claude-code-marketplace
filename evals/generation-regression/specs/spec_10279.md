The solar scheduling models currently plan charging based on raw solar forecast/production figures, effectively assuming all forecasted solar generation is available for vehicle charging. We want to move the scheduler over to using household export power (in watts) — i.e. the solar power actually available for export/charging after accounting for household consumption — so that scheduling decisions reflect a more realistic power budget.

Requirements:
- Introduce/rename the relevant argument(s) passed through the scheduler and its data models (dc/models/solar.py, dc/scheduler/schedule_queries.py, dc/scheduler/solar_and_grid_schedules.py, dc/scheduler/solar_only_schedules.py, dc/scheduler/solar_smart_schedules.py) so they represent household export power in watts, rather than an abstract/unitless solar production or efficiency figure.
- When building combined price/solar data (dc/data/combined_prices.py and the PriceData construction path), convert the solar forecast into watts at the point where PriceData is built, so downstream scheduler code consumes watt values directly instead of needing to know the site's solar capacity to perform a unit conversion itself.
- Update the scheduler logic so that, wherever it previously multiplied a unitless solar efficiency/production fraction by a known solar capacity to get a power figure, it now uses the watt value directly.
- Scheduling must still operate in discrete power steps: whatever step/quantisation logic currently determines how much charging power to allocate at each interval should continue to work correctly against the new watts-based export figures.
- Update dc/models/energy_usage/energy_usage.py and dc/models/energy_usage/percentage_import.py as needed so energy-usage/import-percentage calculations are consistent with the new watts-based household export representation.

Deliverable: schedulers take a household export power (watts) value as input, PriceData carries this value already converted to watts, and scheduler code no longer needs the solar capacity parameter to interpret solar availability, while preserving discrete-power-step scheduling behaviour.
