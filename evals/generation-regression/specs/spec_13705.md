As part of the vehicle onboarding web flow (vehicle_onboarding app), users currently pick their vehicle make via make_selection.html. Add the next step: a model-selection view letting the user pick their specific vehicle model after choosing a make.

Requirements:
1. New template vehicle_onboarding/templates/vehicle_onboarding/model_selection.html presenting the models available for the previously selected make, styled consistently with make_selection.html (reuse/extend static/css/vehicle_onboarding/selection_view.css).
2. New view in vehicle_onboarding/views/generic.py rendering the template, handling GET (display available models for the chosen make) and POST (record the chosen model and advance the flow).
3. URL entry in vehicle_onboarding/urls.py.
4. Add/extend a form in vehicle_onboarding/forms.py for model selection (choice field populated from the available models for the selected make).
5. Minimal update to make_selection.html so submitting a make proceeds to the model-selection step.
6. Test coverage in vehicle_onboarding/tests/test_webflow.py: navigating make -> model selection, selecting a model, flow proceeding correctly, validation/error handling for invalid or missing selections.

Integrate cleanly into the existing multi-step onboarding wizard pattern used by make_selection — same conventions for session/state handling, form rendering, and navigation.
