We need to record Stripe payment/invoice activity in our database to track payments for metrics and later follow-up actions (welcome emails, Solar+ status). Lightweight record — Stripe stays source of truth; persist just enough (amount, type, identifying info) to know a payment happened.

Requirements:
1. New StripeInvoice model in dc/models/stripe_invoice.py: reference to the Stripe invoice/payment identifier, associated user, amount, and a type/category field. Add needed enum(s) to dc/enums/enums.py. Register in dc/models/__init__.py; write migration (dc/migrations/, update max_migration.txt).
2. Django admin registration in dc/admin/payment.py (register in dc/admin/__init__.py).
3. In dc/views/rest/stripe.py, extend the existing Stripe webhook handling so that when invoice/payment data arrives, a task is dispatched to create the StripeInvoice record. Add the Huey task in dc/tasks/payment.py (takes the webhook payload data, creates the row); register in dc/tasks/__init__.py.
4. Add data-conversion helpers (e.g. Stripe amount representation to our currency/decimal conventions) to dc/utils/converters.py.
5. Tests: dc/tests/models/test_stripe_invoice.py, dc/tests/tasks/test_payment.py (creating records from webhook-shaped payloads, handling missing/malformed data), and extend dc/tests/views/rest/test_stripe.py verifying the webhook triggers invoice recording.

Focus on correctly identifying which Stripe webhook event types represent a completed user payment, extracting the right user/amount/type from the event payload, and reliably creating exactly one StripeInvoice record per completed payment.
